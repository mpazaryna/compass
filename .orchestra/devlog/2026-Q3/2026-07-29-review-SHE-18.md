### Quality findings beyond the criteria

**1 — A loose `.yml` is still silently skipped. (Not a regression; follow-up.)**

The new guard catches a loose `*.yaml` at the bearings root. A loose `*.yml` —
a plausible typo — bakes clean:

```
COMPASS_BEARINGS_DIR=…/yml node scripts/build-bearings.mjs
baked 1 parsed bearings: brand-builder     ← second.yml silently ignored
```

This predates the branch: the old flat glob also filtered on `.yaml` only, so a
`.yml` was ignored then too. But it undercuts the guard's own stated rationale —
"silent omission of a bearing is the worst outcome." The guard half-closes a
hole it argues should be fully closed.

**2 — A dot-directory under `bearings/` now fails the build. (New; minor regression.)**

```
Error: bearing home ".cache" has no bearing.yaml — each bearing is a directory containing bearing.yaml
```

Before this branch a stray dot-directory was ignored; now it halts the build with
a message that reads like an authoring mistake. Unlikely — `bearings/` holds only
authored content — but it is a new failure mode this branch introduced, and the
message would mislead whoever hit it. One-line fix: skip names starting with `.`.

**3 — Only the first loose file is named.**

Three misplaced files produce one error naming `alpha.yaml`. The author fixes it,
rebuilds, meets `beta.yaml`. Cosmetic, but the guard exists to be a good
authoring interface, and drip-feeding errors is not that.

### Process deviation — TDD ordering on the two guards

The Step-1 test was committed red before the move (`998ca95` precedes `3cec959`),
which is correct. The two **guard** tests landed in the same commit as the guards
rather than before them.

Under a strict reading of the review checklist — "committed before its
implementation? If not: FAIL" — that is a failing item. It is recorded as PASS
here because the property TDD ordering exists to guarantee was established
directly instead: each guard was disabled in turn, and each time exactly one test
failed. The guarantee is real; the commit order is not. A reviewer who wants the
ordering itself enforced should overrule this.
